# Design
Core `song.js`: `orderEntry`, `normalizeOrder` (accepts integers, drops invalid patterns and self-references), `orderText` / `parseOrderText` (overrides survive when the pattern at a position is unchanged), `trackDataFor(song, entry, trackId)` expands another pattern's track data to the entry's length by looping and clipping, scaling ticks when row sizes differ. `renderSong` iterates entries × repeats, records `entry`, `repeat` and `tracks` on each start, and renders each track from `trackDataFor`. The entry's own pattern sets length, tempo lane and groove. Song version 2; version 1 files load unchanged; a version 1 app rejects version 2 files with a clear message, hence the major bump. UI: chain dialog in `arranger.js`; play-song starts at the first appearance of the open pattern; header shows ▸name on chained tracks while that entry plays.
