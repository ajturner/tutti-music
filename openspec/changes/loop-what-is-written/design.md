# Design
`writtenRows(song, phr, key)` in `src/core/song.js` is the rule: the last tick any instrument's expanded material (loose notes and placements, through `expandMaterial`, so transformations and repeats count) sounds, rounded up to a whole bar from the phrase's meter and row size (`rowsPerBar(phr)`, also new in the core), clamped to the phrase's rows; zero written gives the phrase's rows. `renderSong(song, { phrases, trim: true })` renders each listed phrase with a copy whose `rows` is its written rows, so the start's `rows`, the length, the groove map and the clipping all follow without another code path; the section and arrangement renders never pass `trim`. `playPhrase` passes `trim: state.loopWritten`, clamps a start from the cursor to the loop (a cursor past the end starts at row 0), and records the loop's rows on the render as `loopRows`.

Live edits: `withUndo`, `withSongUndo` and history swaps call `refreshLoop()` in `src/ui/transport.js`, which, while a phrase or pattern loops and no other phrase is queued, queues a fresh render of the same thing; the scheduler swaps at the loop boundary, so the change and any new length are heard next time round. `sched.onSwap` leaves the cursor and the open phrase alone when the swap is the same phrase or a pattern.

The grid dims rows from the loop's end (`loopRowsOf(phr)` in `src/ui/state.js`, the written rows when the rule is on, else the phrase's rows) with a translucent wash over the content and the gutter and writes ↻ in place of the row number on the end row, only when that is before the phrase's end. The pocket's Phrase and Pattern levels add class `past` to those rows. The status reads `playing (loop 2 of 4 bars) row 5` when the loop is shorter than the phrase. The View toggle is `#loopWritten`, `state.loopWritten`, stored as `tutti.loopWritten.v1`. No song JSON change.
